# Team memory — Airlinq IoT Platform

Curated index of team-wide learnings. Only Jarvis writes here (promotes `Team-learning candidate` lines from role sign-offs). One line per learning; prune what stops being true.

- Build/deploy gotchas (Windows laptop, air-gapped server) are recorded in `HANDOFF.md` §3, §4.2, §8.6 — read them before any build or deploy.
- Colours always come from `--aq-*` tokens in `ui-ngx/src/styles.scss` (never hex outside the token blocks). The old "no template edits at all" rule is superseded: template/TS edits are allowed when the spec needs structure CSS cannot create, but they must stay additive and merge-friendly (this is a ThingsBoard fork) - see docs/adr/0001.
- A spec is only reachable if the delivery constraint can express it: the dashboard/grid canvas was "implemented" twice under a CSS-only rule that cannot create missing DOM, flip a mode-toggle, or beat inline styles written by TS. Check spec-vs-constraint reachability at G1.
- Theme scoping: `<body class="tb-default">` is STATIC and only `tb-dark` is added on top, so a `.tb-default`-scoped rule also matches in dark; paired token blocks (light 1428 / dark 1478, equal specificity, dark later) flip the colours. A `.tb-default`-only block is a maintainability booby-trap, NOT a dark-mode bug — do not diagnose missing dark styling from the selector alone.
- Repo gates are ALREADY RED on a pristine tree - measure a baseline before coding: `yarn lint` gives 569 problems / 462 errors (and OOMs unless `NODE_OPTIONS=--max-old-space-size=8192`), `mvn license:check` had 7 untracked offenders; 4 fixed 2026-09-05 by a pom exclude, 3 remain locally (gitignored `.superpowers/`, invisible to CI), and `netty-mqtt` tests need Docker (absent). Only the before/after DELTA is meaningful; no CI workflow runs `yarn lint`.
- Never run `mvn license:format` blindly here: it would inject Apache headers into the design-canvas `.dc.html` spec artboards under `docs/design/` and corrupt the source of truth. The root pom now excludes `docs/design/**/*.dc.html` (committed spec files) so `license:check` stays green in CI without formatting them. Locally it still reports 3 `Missing header` warnings for gitignored `.superpowers/` files - CI never sees those (gitignore:55), and license-maven-plugin 3.0 has no gitignore-aware option (that is 4.x), so the local red is expected and accepted.
- Adding an entity-table column type needs FIVE coordinated edits: the `EntityTableColumnType` string union, the `EntityColumn` union, the `EntityColumnsType`/`EntityColumnType` `Partial<A & B & C>` intersection the template binds against, every call site's `Array<EntityTableColumn<X>>` widened to `Array<EntityColumn<X>>`, and the `instanceof` filter that builds `entityColumns` in `entities-table.component.ts` (`columnsUpdated()`). Edits 3-4 fail at build time (TS2339 / TS2740); edit 5 fails only at RUNTIME - see the `entityColumns` note below.
- Angular >= 15: a string `[class]="expr"` binding REPLACES the static `class` attribute (silently dropping base classes). Use discrete `[class.foo]="cond"` bindings when a static class must survive.
- `columnsUpdated()` builds TWO arrays that must stay in step: `entityColumns` (filtered by `instanceof`, drives the `matColumnDef` loop in the template) and `displayedColumns` (built from the UNFILTERED config, drives `mat-table`'s row rendering). A column class missing from the `instanceof` filter lands in `displayedColumns` with no matching column def, and `mat-table` throws `Could not find column with id "<key>"` at runtime - it builds clean, lints clean and passes every grep while rendering a broken table. Structural proof is not visual proof: only a browser confirms the table renders.
- Test-criteria applicability must be derived from RUNTIME behaviour, not config flags: `selectionEnabled` is ANDed with the enabled group-action count and Delete is auto-appended, so a flag predicts neither checkboxes nor bulk actions. Likewise `displayPagination=false` is set by no config in this repo.
- The shared entity table has ~46 consumers (39 routed pages + 7 wrapper tables in drawer tabs/dialogs), not the "7 additional"/"10+" quoted in earlier docs. Size regression sweeps against that number.
- The portable toolchain at `d:/tmp/tools` (JDK 25 + Maven 3.9.9) is NOT on the default PATH: a bare `which mvn` / `java -version` reports it missing and looks like an environment blocker. Always export JAVA_HOME/PATH per the overlay before concluding a tool is absent.
- Assert `getComputedStyle`, and prove any CSS specificity diagnosis by INJECTION - never by reading the file. In `styles.scss` the anatomy rules are `.tb-default .mat-mdc-header-row` (0,2,0) while pre-existing upstream rules nest one level deeper, e.g. `.tb-default .mat-mdc-table .mat-mdc-header-row` (0,3,0) at ~:747-758, which wins regardless of source order. `!important` does NOT rescue a lower-specificity rule when the winner is also `!important`; match or exceed the selector depth instead.
- A CSS rule can be present, correct, dual-scoped AND `!important` and still never apply. That is the same failure class as the two earlier "looks the same" rounds - the fix must be verified in the rendered page, not in the stylesheet.
- Entity-table header band is 40px (AC-2). This supersedes the 44px recorded in HANDOFF section 8.6 and the 44px that shipped in the anatomy block.
