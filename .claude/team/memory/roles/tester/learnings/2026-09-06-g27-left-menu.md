# G2.7 + execution — left-menu-and-favicon (run-1), 2026-09-06

## What happened
Drafted the 58-case G2.7 list and executed it in one block. 44 PASS, 1 PASS-with-limitation,
6 FAIL, 2 BLOCKED, 1 N/A(human). Two of the six findings share one root cause.

## Learnings

- **`.tb-dark { ... }` genuinely does NOT match in light — the mirror of the earlier `.tb-default`
  lesson.** `styles.scss` has a "DARK-ONLY additions" block opening at :1620 whose header says every
  rule inside is `.tb-dark`-scoped. The AC-24 hover lift (:1683), the AC-29c `:focus-visible` ring
  (:1697) and the sidebar hover/active colour rules (:1669, :1704) were all written INSIDE it, so
  they work in dark and are absent in light. Team memory's "a `.tb-default`-scoped rule also matches
  in dark" does not invert — **always resolve the enclosing selector chain by parsing brace nesting,
  never by reading the nearest heading comment.** A 20-line python brace walker over the file gave
  the chain (`.tb-dark > .tb-site-sidenav ...`) in seconds and turned a vague "rule doesn't apply"
  into a precise one-line fix.
- **Run every theme-sensitive criterion in BOTH themes before writing the verdict.** Dark passed
  AC-24 and light failed it. Had I probed dark first and generalised, I would have signed off a
  broken light theme; had I probed only light, I would have reported the rule as entirely dead.
- **Injection proof still beats reading CSS, and it also distinguishes "outranked" from "scoped
  out".** Element matched `:focus-visible` (`el.matches(':focus-visible') === true`) while
  `outline-style` computed `none`; injecting the same declaration at higher specificity painted the
  ring. That result is identical for both failure modes — the brace walk is what separated them.
- **`preventDefault()` not firing is the cheapest proof a handler never ran.** Instrumenting the tile
  with capture+bubble keydown listeners and reading `event.defaultPrevented` after a real dispatched
  `KeyboardEvent` showed Enter reaching the element with `defaultPrevented:false`, while
  `ng.getComponent()` confirmed `collapsed===true` and `toggleTile` bound — i.e. every guard in
  `onTileKeydown` should have passed. Proves "the Angular binding is not firing" without reading TS.
- **A stateful setting that persists SERVER-side makes probes non-idempotent.** `menuCollapsed` is
  stored per user, so my first "click the pin" run flipped it and the second run's blind click
  collapsed the menu instead — the probe silently measured the wrong state and exited. Always assert
  the TARGET state and toggle only if needed (`if (width < 200) click()`), never blind-toggle.
- **One browser profile cannot serve two concurrent Playwright processes.** Running the 140 s network
  capture alongside the dark probes killed both with "Target page, context or browser has been
  closed". Parameterise the profile dir (`process.env.UDD`) from the start.
- **`yarn lint` and `mvn install` must not overlap** — lint died with exit 134 / "Reached heap limit"
  at 8 GB while Maven compiled. The jarvis brief said "stop the dev server before lint"; the same
  applies to the build. Serialise all three.
- **Playwright `isVisible()` round-trips are too slow to time a ~300 ms animation** — they made a
  300 ms close-delay look like 3 s and nearly produced a false AC-29 failure. Sample INSIDE the page
  with `requestAnimationFrame` into `window.__samples`, then read the array once.
- **Scope a "does every row navigate" sweep to top-level rows.** `li > tb-menu-link a` also matches
  rows inside collapsed toggle sub-lists (`visibility:hidden`, height 0); clicking them times out and
  reports 13 false failures. `:scope > li > tb-menu-link > a` gave the true 10/10.
- **Regex-parsing a 1139-line nested TS model for a route-parity diff is not evidence.** My first
  pass reported LOST `/alarms`, `/notification` and GAINED `/profiles`; comparing those ids directly
  across revisions showed them byte-identical. The authoritative check is the RENDERED menu per
  authority, plus driving the real `MenuService.homeSections()` through `ng.getComponent` for D9.
- **Criterion wording goes stale against later decisions — say so instead of failing it.** AC-11 says
  "five true sub-menus" but D2 added Edge management (six); AC-22 says the dot is on "the Monitor
  tile" but headings are `display:none` in the rail so it sits on Alarms. Both implementations meet
  the criterion's measurable intent exactly. Recorded PASS + a note routed to Jarvis, not a finding.

**Team-learning candidate:** `styles.scss` has a `.tb-dark`-only block (opens :1620, header
"DARK-ONLY additions"). Rules added there are invisible in light. Resolve the enclosing selector by
walking brace nesting, not by trusting the nearest comment — this cost 2 of 6 G3 findings this round.
