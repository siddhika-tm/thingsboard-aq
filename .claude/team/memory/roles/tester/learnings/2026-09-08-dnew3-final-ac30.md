# Tester learnings — D-NEW3 final verification (AC-30 unblock), 2026-09-08

Work item: airlinq-blue-light-recolour. One-line selector narrowing at `ui-ngx/src/styles.scss:1737`
(`background-color: …` -> `@at-root body#{&} { background-color: … }`). Verdict: cleared.

## Method learnings

- **A same-server self-comparison is the only way to attribute a small pixel delta.** Cross-server
  pristine-vs-worktree showed 34 px in a 7x7 box on `/entities/devices` and `/entities/assets`.
  Running the SAME server twice reproduced the IDENTICAL 34 px / 7x7 @(140,224) artifact, while a
  second cross-server pass measured 0. The delta was live alarm-badge churn, not CSS. Without the
  same-server control this would have read as a real regression (or been hand-waved away).
  Corroborating signal: `/alarms` row count moved 6 -> 5 between runs on its own.

- **Measure the noise floor BEFORE choosing pixel targets, and let it pick them.** Two runs of the
  same server: `/entities/devices`, `/entities/assets`, `/alarms`, `/profiles/deviceProfiles` all
  0 px; `/home` self-differed 65,197 px / **4.07%** (animating widgets + streaming telemetry).
  `/home` is unusable as a pixel target and must be excluded, not explained away.

- **`p.goto()` per route triggers a full SPA reload and races the loading spinner.** The first dark
  sweep produced a 97% whole-surface "difference" that was just a spinner screenshot on one side.
  Symptom to recognise: EVERY route differs by the same huge count with an identical bounding box.
  Fix: after navigation, `waitForFunction` on *spinner-not-visible AND (rows > 0 || empty-state ||
  widgets > 0)`, then assert the rendered state (`rows`, `spinnerVisible`) into the result row so a
  non-rendered capture cannot silently become evidence.

- **`playwright-core`'s `evaluate()` returns `undefined` for a STRING arrow function.** Passing
  `'() => ({...})'` yields `undefined` with no error, which surfaced as
  `Cannot read properties of undefined (reading 'length')` far from the cause. Pass a real function.

- **Concurrent Playwright runs against one dev server can transiently fail login**
  (`Unhandled error code 'Unknown'`, empty username field). Guard with an explicit post-login
  `loggedIn` assertion that THROWS — and place it before any screenshot is written, or a failed
  login still leaves 7 authoritative-looking PNGs on disk.

- **`ng serve` in a second worktree needs no `--proxy-config` flag** — `angular.json` already points
  at `proxy.conf.js`, so editing the throwaway worktree's copy is enough. The MAIN tree's tracked
  `proxy.conf.js` never has to be touched: pass a copy via `--proxy-config` instead. This avoids the
  LF->CRLF dirty-file trap entirely rather than reverting it afterwards.

- **Reconcile a `node_modules` entry count before reporting it.** Post-teardown `ls | wc -l` gave 918
  against 920 pre-run and looked like deletion; `ls -A` restored 920 (`.bin`, `.yarn-integrity`).
  Delete the junction with `(Get-Item $j).Delete()` (removes the reparse point, not the contents).

- **Verify a port is closed BY REQUEST, not by kill confirmation.** `curl -> 000` plus no LISTENING
  socket. `Get-CimInstance Win32_Process` filtered on CommandLine finds the real PIDs (`ps -W`
  prints memory, not PIDs).

## Product/mechanism learnings

- **The dark auth div keeps its dark paint through a DESCENDANT rule, and that is what makes the
  narrowing safe.** Measured on the div (`tb-password-content mat-app-background tb-dark`):
  light -> `matches('.tb-dark .mat-app-background') === false` (body lacks `tb-dark`, no ancestor)
  so it paints `--aq-auth-bg` `#eef1f7`; dark -> the same selector matches `true` via
  `<body class="tb-dark">` as ancestor, painting `rgb(10,13,18)`. Both themes verified. A theme
  asymmetry in an ANCESTOR is what lets a narrowing fix light without touching dark — check the
  descendant-rule match state per theme, never just the element's own class list.

- **`matches('.tb-dark') && !matches('body.tb-dark')` is the exact affected-set probe** for this
  class of change. Swept 9 authenticated + 5 auth routes x 2 themes: authenticated `affected=0`
  in both themes (body is the only carrier and still matches), auth `affected=1` (the one root div).
  This turns "did anything else regress?" into an enumeration instead of an argument.

- **A frozen-block digest changing is not evidence of a content change.** Digest moved
  `788af402…` -> `ed306ea2…` while the sorted declaration multiset diffed to ZERO (75/75 by name
  and value) and the raw block diff was a single selector wrapper. Report the declaration multiset
  as the load-bearing proof and treat the hash as an index. My parser counted 75 where the work item
  states 82 — a declaration-counting convention difference; publish the convention with the count,
  the same lesson already recorded for the hash itself.

- **Attribute every difference to a specific diff hunk before calling it a regression.** Dark
  `/login` differed by 39,379 px; the mask's doubled text showed a vertical card offset, and
  `git diff` pinned it to the removed `OPERATOR CONSOLE` strip in `login.component.html` plus
  18/15 lines of `login.component.scss` — separate G4-approved work in the same item, not D-NEW3.
  Confirmed independently: `body` matches `body.tb-dark` and paints `rgb(10,13,18)` on BOTH servers.

**Team-learning candidate:** A small cross-server pixel delta means nothing until the same server is
compared against itself. Live data (alarm badges, row counts, telemetry) reproduces byte-for-byte
across two builds only by luck; run the self-comparison first and subtract that artifact. Related:
measure a per-route noise floor and let it choose the pixel targets — `/home` self-differs ~4%.

**Team-learning candidate:** When a bare-class selector is narrowed with a type qualifier
(`.x` -> `body.x`), the safety argument is structural (a `<div>` cannot satisfy `body`) but the
*preservation* argument usually rests on a DESCENDANT rule that still matches via the ancestor.
Prove both directions per theme with `Element.matches()` on the real element, plus a PNG decode.
